# AGENTS.md

[English](AGENTS.md)

P4 Language Tools — расширение VS Code для P4₁₄ и P4₁₆. Команды ниже выполняются из корня репозитория. Основные тесты используют встроенный раннер Node.js 20+, для упаковки нужен Python 3.

## Где менять код

- `extension/package.json` объявляет команды и настройки VS Code. Их обработчики и клиент LSP находятся в `extension/src/extension.js`.
- `server/src/server.js` обрабатывает запросы LSP. За объявления и области видимости отвечает `indexer.js`, за сигнатуры — `signatures.js`, за комментарии к объявлениям — `docs.js` в той же папке. При изменении запроса или уведомления сверяй обе стороны протокола. Сервер использует stdout для JSON-RPC, а stderr для отладочных сообщений.
- `extension/syntaxes/p4.tmLanguage.json` задаёт подсветку TextMate. Категории имён, зависящие от объявлений, определяет `server/src/semantic.js`. При изменении общей логики проверяй оба диалекта. Встроенный ANTLR-парсер обслуживает P4₁₆.
- `server/compiler.js` запускает внешний компилятор и разбирает его вывод. `server/src/server.js` объединяет результаты с диагностикой редактора и публикует их в VS Code.

## Что учитывать при изменениях

Навигация, подсказки и диагностика при вводе работают с текущим текстом открытых буферов. Компилятор читает файлы с диска и использует настроенную точку входа. Внешний процесс запускается только в доверенном рабочем пространстве, с аргументами в виде массива и `shell: false`.

Привязывай ошибку к файлу, указанному компилятором. Это может быть закрытый `#include`. Диапазоны LSP отсчитываются с нуля в единицах UTF-16. Для нового формата лога добавь пример в `server/compiler.test.js` и проверь, какой текст выделяется. Сообщение без координат остаётся в канале **P4 Compiler**.

## Проверка

Основной набор запускает модульные тесты и отдельный процесс LSP. Тесты клиента имитируют API VS Code, тесты компилятора используют исполняемый файл из фикстуры.

```sh
node --test server/compiler.test.js server/test/*.test.js test/*.test.js extension/test/*.test.js
```

Дополнительные проверки зависят от того, что изменилось.

- Для грамматики TextMate выполни `(cd test/textmate && npm ci && npm test)`.
- Для диагностики настоящего компилятора задай `P4TEST_16` и `P4TEST_14` с путями к подходящим исполняемым файлам и запусти `node --test test/real-compiler.cjs`. Без соответствующей переменной тест диалекта пропускается.
- Для проверки установленного расширения собери VSIX и запусти сценарий для настольного VS Code или VS Code Server. [Инструкции для обоих режимов](test/vscode/README.md).

## Сборка и релизы

Команда `python3 build_vsix.py` создаёт в корне VSIX с версией из `extension/package.json`. Пакет включает `extension/README.md`. При изменении пользовательских функций обновляй его вместе с корневым `README.md` и переводом `README.ru.md`. Готовый VSIX прикрепляется к GitHub Release для соответствующего тега. Маска `*.vsix` в `.gitignore` исключает локальные сборки из коммитов.
